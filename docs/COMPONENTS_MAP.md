# Components map

Swimlane grid required by the exam booklet: actors as rows; Trigger, Input, Context, Processing, AI and Output as columns.
Generated from `src/lib/componentsMap.ts` (run `npm run gen:map`), which also feeds the in-app page at `/guide/map`.

The one rule: code picks, validates and scores; Gemini Flash only writes explanation text from numbers the code produced.

| Actor | Trigger | Input | Context | Processing | AI | Output |
|---|---|---|---|---|---|---|
| **Aryan** (The user) | Opens a match, edits and confirms a team, enters points, accepts or rejects a proposal | PIN, swaps and captain choices, real Dream11 points, manual roles, accept or reject | Sees the agent's team, the reasons, and live rule checks on phone or laptop; can edit until the match starts | None | None | A confirmed team that he enters in Dream11 himself; approved rubric versions |
| **Data jobs (run outside Vercel)** (Scripts: ingest, roles, weather, credits) | A command today (npm run ingest:cricsheet, fetch:weather); a scheduled job later | Cricsheet ball-by-ball files (T20Is, IPL, Syed Mushtaq Ali), Open-Meteo weather | League and competition tier, match date, no scraping inside Vercel functions | Translate every ball into per-player match rows; infer roles from what players did; seed credits | None | Rows in Supabase, each labelled ingested, computed or seeded |
| **Supabase** (Storage (Postgres)) | Reads and writes from scripts and server code | 24 tables: matches, players, stats, recommendations, actual points, rubric versions, audit log | Row Level Security on with no public access; only the server key can read or write | None | None | History, recommendations, predicted and actual points, versions |
| **Rules and points config** (Data, not code) | Loaded whenever a team is validated or a player is scored | Team rule profiles (strict, loose), points tables (standard, variant), rubric parameters | Every value carries its source and how sure we are (certain to unverified) | None | None | The numbers the engine and validator read |
| **Prediction and selection engine** (Plain TypeScript) | The backtest command (a toss-time run is the planned live trigger) | Only matches before the match date; predicted or confirmed XI; seeded credits; weather; venue history | As-of date prevents peeking; missing data stays unavailable; active rubric version | Expected points (form, venue, team form, death-over rule, role correction); exact best legal team; captain and vice-captain; rules validator | None. The AI never picks a player or checks a rule | Recommended 11, captain, vice-captain, and the numbers behind every pick |
| **Gemini Flash** (AI (gemini-3.8-flash)) | After a recommendation is stored (npm run explain) | A packet of numbers the engine produced for each pick and the match | Instructions: use only those numbers, no win predictions, no calculations of its own | A code guard rejects any sentence with a number not in the facts; plain templates replace rejected ones | Writes the reason for each pick, the captain and vice-captain reasons, the pitch report and the team summary, as JSON | Reason text saved with each pick, plus an audit log of accepted and rejected sentences |
| **Web app (Vercel)** (Next.js dashboard behind a PIN) | Aryan visits a screen or submits a form | Supabase, read through server code only; typed Dream11 points and role overrides | Every action checks the PIN itself; layout works on phone and laptop | Renders matches, predicted vs actual bars and reasons; the team editor re-runs the same rules checker on every edit and again on the server before saving; saves only the values Aryan changed | None at runtime. The reasons were written earlier and are only displayed | Matches, match view, Learning, Data and Guide screens |
| **Learning loop** (Deterministic maths plus a human decision) | Aryan saves a match's points (automatic mode), or the Look for patterns button, or npm run calibrate | Predicted and actual points for every player in every final team | Needs about 20 compared players and 3 matches; a role needs enough rows of its own; one cycle moves a value by at most 20%, and automatic mode applies half of that, inside a safe range of 0.6 to 1.4 | Average error and bias by role and by pitch type; proposes a per-role correction factor; in automatic mode applies it as a new rubric version, in ask-first mode waits for Aryan | None | A new rubric version the next match uses (undoable), or pending proposals; accuracy shown per version |
