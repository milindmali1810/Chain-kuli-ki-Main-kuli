## Decisions made
- Stack: Next.js (TypeScript) + Supabase + Vercel, as in Milind's earlier builds. Access via shared PIN.
- Scope: men's T20I only for the demo; league is a config field.
- Selection and validity are deterministic code. Gemini only writes reasoning text.
- Rules and points tables are config data. Team rules default to the strict profile (7 per team, WK 1-4, BAT 3-6, AR 1-4, BOWL 3-6) because the real rule is in conflict across sources (7 vs 10; role limits 1-8). Points default to the "standard" profile (four +1, six +2). See RULES_LOCKED.md.
- No win or loss prediction. Team Form Index is a capped soft factor (about 8 percent) that the learning loop can test and switch off.
- Death-bowler rule is data-defined with a guaranteed slot unless clearly outscored; no names hardcoded.
- Predicted XI is labelled "predicted" until confirmed; Dream11 credits are entered manually.
- Data: Cricsheet primary (free ball-by-ball), Apify actors supplementary, weather API free, Gemini grounding for pitch report text; ingestion runs outside Vercel and writes to Supabase.
- Learning loop proposes versioned changes only; Aryan approves.
- Backups feature flag off by default (rule not verified).

- Model gemini-3.8-flash via the Interactions API (POST https://generativelanguage.googleapis.com/v1beta/interactions, header x-goog-api-key, body model + system_instruction + input + response_format{type text, mime_type application/json, schema}; answer = last step of type model_output). - Files: src/lib/gemini.ts (client, fetch injectable, never leaks the key), src/lib/reasoning.ts (facts packet types, prompt, schema, GUARD, templates, assembleExplanation), scripts/explain.ts (`npm run explain -- --match ID [--no-gemini]`), supabase/migrations/20261011_002_explanations.sql (recommendations.captain_scores_json, engine_notes_json, captain_reason, vc_reason, summary_text; applied).
- The guard (plain code, the key defence against AI invention): every number in a Gemini sentence must exist in the facts; a pick's sentence may only use THAT player's numbers plus the match context (stops a number borrowed from another player); whole-number rounding only for numbers 10 and above (a first version let "3 centuries" through because 2.5 rounded to 3: caught by a test); win/loss predictions rejected; no derived numbers (Gemini once computed 43.5 - 41.8 = 1.7: rejected). A rejected or missing sentence is replaced by a template built only from the facts, and templates are tested to pass the same guard. If Gemini is down everything falls back to templates.
- Prompt rules added after reading real output: cite the MOST RECENT scores in order (not the highest), flag high blank-match rates, death-over numbers are last 24 months (field renamed deathBallsLast24Months), only role-relevant stats are sent, no field names or word "null" in prose, no own calculations.
- Audit trail: each run inserts an ingestion_runs row (source gemini-explain) with model, calls, failures, sentences accepted, replaced and the rejected reasons. Demo match 1529230: 32/32 accepted on the last run (earlier run: 31 accepted, 1 rejected). Match 1552777 (provisional only, no weather): 15 accepted, 1 replaced ("24" not in facts).
- Stored: recommendation_players.reason_text (+ factors_json.reasonSource gemini|template), recommendations.captain_reason / vc_reason / summary_text, match_context.pitch_report_text (final stage). Tests: 212 passing.
- Honest limits: the explanations can only cite what the engine computed (recent scores, role stats, venue, team form, death numbers). Team-form effect repeats across a side's players because it is a side-wide multiplier. Matchups, spin vs pace, toss/dew are unavailable and the pitch report says so.
